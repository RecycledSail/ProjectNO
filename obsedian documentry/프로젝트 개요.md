# 프로젝트 개요

## 한 줄 요약

이 프로젝트는 Unity로 만든 국가 운영 시뮬레이션 게임이다.

플레이어는 하나의 [[Nation]]을 조작하며, 지역, 인구, 생산, 시장, 재정, 건설, 연구, 군대, 외교가 주 단위로 갱신되는 구조를 가진다.

## 현재 코드 기준 핵심 구조

```text
JSON 데이터
  ↓
[[GlobalVariables]]
  ↓
GameManager
  ↓
[[Nation]] / Province / Market / EconomicEngine
  ↓
UI, 저장/불러오기, 전투, 건설, 재정
```

## 문서 허브

- [[GlobalVariables]]: JSON 데이터를 읽어 전역 런타임 데이터로 구성하는 부트스트랩 클래스
- [[Nation]]: 국가 하나를 표현하는 중심 모델
- [[GovernmentBudget]]: 국가의 세금, 통화 발행, 정책 예산, 인플레이션 처리

앞으로 추가하면 좋은 문서:

- [[GameManager]]
- [[Province]]
- [[EconomicEngine]]
- [[Market]]
- [[Building]]
- [[ConstructionRequest]]
- [[Diplomacy]]
- [[Regiment]]
- [[SaveManager]]
- [[UI 시스템]]

## 게임 시작 흐름

게임 시작 시 `GameManager.Start()`가 실행된다.

1. `GlobalVariables.LoadData()` 호출
2. `Assets/Resources/*.json`의 기본 데이터 로드
3. 저장 파일이 있으면 `SaveManager.OnLoad()` 실행
4. 저장 파일이 없으면 `StartNewGame("Nation1")` 실행
5. 플레이어 국가와 유저 생성
6. UI 초기 갱신
7. 날짜 진행 코루틴 시작

`GlobalVariables`는 국가, 지역, 상품, 건물, 연구, 외교 초기값 같은 정적 데이터를 먼저 만든다. 이후 `GameManager`가 이 데이터를 실제 게임 세션의 `nations`, `provinces`, `users`, `player`로 연결한다.

## 주요 시스템

## 데이터 로드 시스템

담당 파일:

- [[GlobalVariables]]
- `Assets/Resources/*.json`

역할:

- JSON 파일을 읽는다.
- JSON wrapper를 실제 게임 객체로 변환한다.
- `BUFF`, `RESEARCH_NODE`, `NATIONS`, `PROVINCES`, `PRODUCTS`, `BUILDING_TYPE` 같은 전역 Dictionary를 채운다.
- 데이터 간 참조를 연결한다.

현재 중요한 특징:

- 대부분의 키가 `id`가 아니라 `name` 문자열이다.
- 로드 순서 의존성이 강하다.
- `LoadData()` 재호출 시 Dictionary 초기화가 부족할 수 있다.

## 게임 진행 시스템

담당 파일:

- [[GameManager]]

역할:

- 싱글톤 형태로 전체 게임 세션을 관리한다.
- 날짜, 일시정지, 게임 속도, 플레이어 유저를 관리한다.
- 일간/주간 이벤트를 호출한다.
- 도로 연결 캐시를 만들고, 국가 시장으로 생산품을 이동시킨다.

주간 처리의 큰 순서:

1. 시장의 `LastSupply`, `LastDemand` 초기화
2. 국가별 수도 연결 캐시 갱신
3. 국가 주간 처리
4. 지역 생산
5. 연결된 지역의 생산품을 국가 시장으로 이동
6. 인구의 식량 소비
7. 인구 갱신
8. GDP 계산
9. 세금, 통화 발행, 인플레이션 처리

## 국가 시스템

담당 파일:

- [[Nation]]
- [[GovernmentBudget]]
- [[Diplomacy]]
- [[Regiment]]

역할:

- 국가의 소유 지역, 수도, 자금, 연구, 버프, 군대, 외교 관계를 가진다.
- 국가 시장과 정부 예산을 가진다.
- 국가 단위 건설 큐를 가진다.
- 주간 턴에서 건설 노동력과 건설 진행을 처리한다.

현재 중요한 특징:

- `Nation`은 많은 하위 시스템을 직접 들고 있는 중심 모델이다.
- 국가의 경제 상태 일부는 `NationMarket`과 `GovernmentBudget`에 있다.
- 외교 관계는 `Diplomacy`가 각 국가의 `allies`, `enemies`에 직접 등록한다.

## 지역과 인구 시스템

담당 파일:

- [[Province]]
- `EthnicGroup`
- `ProvinceEthnicPop`
- `SpeciesSpec`
- `Culture`

역할:

- 지역은 국가 소유, 지형, 인구, 건물, 특수 건물, 지역 시장을 가진다.
- 인구는 종족, 문화, 재산, 생활 수준, 연령대 같은 정보를 가진다.
- 지역은 매일 또는 매주 인구와 생산 관련 처리를 수행한다.

현재 중요한 특징:

- 지역의 `nation` 참조와 국가의 `provinces` 리스트가 양방향으로 맞아야 한다.
- 수도와 도로 연결 여부에 따라 국가 시장을 쓸지 지역 시장을 쓸지가 달라진다.

## 경제와 시장 시스템

담당 파일:

- [[EconomicEngine]]
- [[Market]]
- `Products`

역할:

- 상품별 재고, 가격, 최근 공급량, 최근 수요량을 관리한다.
- 지역 시장과 국가 시장이 분리되어 있다.
- 도로로 수도와 연결된 지역의 생산품은 국가 시장으로 이동한다.
- 인구 소비는 연결 상태에 따라 국가 시장 또는 지역 시장에서 처리된다.
- GDP는 국가 시장에 들어온 상품의 `LastSupply * Price`로 계산된다.

현재 중요한 특징:

- 시장 가격은 수요/공급 기반으로 갱신된다.
- `GovernmentBudget`의 인플레이션은 국가 시장 가격 지수를 기반으로 한다.

## 재정 시스템

담당 파일:

- [[GovernmentBudget]]
- `BudgetUI`
- `FinanceUI`
- `IndustrySubsidyPanel`

역할:

- 평균 GDP 기준으로 세금을 걷는다.
- 정책 배정액을 통화 발행으로 투입한다.
- 연구, 군사, 산업, 부동산 정책 효과를 적용한다.
- 국가 시장 가격 기반으로 인플레이션을 계산한다.

현재 중요한 특징:

- `BudgetUI`는 평균 GDP 기준으로 발행 가능액을 잡는다.
- `FinanceUI`는 주간 세입 기준으로 정책 비율을 잡는다.
- 둘 다 같은 `PolicyAllocation`을 수정하므로 기준 통일이 필요할 수 있다.

## 건설과 생산 시스템

담당 파일:

- [[Building]]
- [[ConstructionRequest]]
- `BuildUI`
- `BuildProvinceUI`
- `BuildQueueItem`

역할:

- 건물 타입은 필요 자원, 생산품, 필요 노동자 수를 가진다.
- 지역은 건물 목록을 가진다.
- 국가는 건설 요청과 건설 진행 큐를 가진다.
- 건물은 노동자를 고용하고 상품을 생산한다.
- 산업 보조금은 건물의 자금에 들어가고 고용을 유도한다.

현재 중요한 특징:

- `Nation.AddToBuildQueue()`는 `BUILDING_RECIPE`에서 건설 시간을 가져온다.
- 특수 건물 건설 큐는 아직 완전히 구현되지 않은 상태다.

## 연구와 버프 시스템

담당 파일:

- `ResearchNode`
- `Buff`
- [[GlobalVariables]]
- `ResearchUI`

역할:

- 연구는 비용과 버프 목록을 가진다.
- 국가는 완료된 연구 목록을 가진다.
- 연구 버프는 국가 생성 시 `BuffKind`별로 합산된다.

현재 중요한 특징:

- 연구 데이터는 `ResearchNodes.json`에서 로드된다.
- 연구가 실제로 진행되고 완료되는 흐름은 추가 문서화가 필요하다.

## 군대와 전투 시스템

담당 파일:

- [[Regiment]]
- `Squad`
- `UnitType`
- `Battle`
- `BattleManager`
- `ArmyUI`

역할:

- 국가는 여러 연대를 가진다.
- 연대는 위치 지역과 분대 목록을 가진다.
- 분대는 병종, 수용량, 실제 병력 수를 가진다.
- 적대 국가의 연대가 같은 지역에 있으면 전투 조건이 된다.

현재 중요한 특징:

- 적대 여부는 `nation.enemies.ContainsKey(otherNation)`으로 확인한다.
- 병종 기본 데이터는 `UnitTypes.json`에서 로드된다.

## 외교 시스템

담당 파일:

- [[Diplomacy]]
- [[Nation]]
- [[GlobalVariables]]

역할:

- 초기 외교 관계는 `InitialDiplomacies.json`에서 로드된다.
- `Diplomacy` 객체가 생성되면 각 국가의 `allies` 또는 `enemies`에 관계가 등록된다.
- 동맹과 적대 관계는 서로 배타적으로 처리된다.

현재 중요한 특징:

- `Diplomacy` 객체 생성 자체가 관계 등록을 수행한다.
- 별도 외교 관계 목록 저장소는 아직 명확하지 않다.

## 저장과 불러오기

담당 파일:

- [[SaveManager]]
- `SaveUI`
- `LoadSelectUI`
- `LoadButtonUI`

역할:

- `Application.persistentDataPath`에 JSON 저장 파일을 만든다.
- 저장 파일 이름은 `GlobalVariables.saveFileName`에 들어간다.
- 저장 시 국가, 지역, 유저, 날짜 정보를 기록한다.
- 불러오기 시 `GlobalVariables`의 기본 객체를 기반으로 세션 상태를 복원한다.

현재 중요한 특징:

- 저장 범위가 아직 제한적이다.
- 국가 예산, 시장 상태, 외교 상태, 군대 상태, 수도 등이 완전하게 저장되지 않을 수 있다.

## UI 시스템

담당 파일:

- `UIManager`
- `NationUI`
- `ProvinceUI`
- `ProvinceDetailUI`
- `MarketUI`
- `BudgetUI`
- `FinanceUI`
- `BuildUI`
- `ArmyUI`
- `ResearchUI`

역할:

- 플레이어가 국가, 지역, 시장, 예산, 건설, 군대, 연구 정보를 확인하고 조작하게 한다.
- `GameManager.dayUIEvent`를 통해 날짜 진행에 맞춰 갱신된다.
- 대부분 현재 플레이어 국가인 `GameManager.Instance.player.nation`을 기준으로 동작한다.

## 현재 코드에서 보이는 개발 방향

현재 구조상 프로젝트는 다음 방향으로 확장되고 있다.

- 국가 단위 경제와 지역 단위 경제의 분리
- 도로/수도 연결에 따른 국가 시장 접근
- GDP, 세입, 통화 발행, 인플레이션을 가진 재정 시스템
- 건물별 노동자 고용과 생산
- 산업 보조금으로 특정 건물 타입 지원
- 인구 집단의 재산과 생활 수준 변화
- 국가 간 외교와 전투 조건

## 우선 문서화하면 좋은 다음 파일

1. [[GameManager]]
2. [[Province]]
3. [[EconomicEngine]]
4. [[Market]]
5. [[Building]]
6. [[SaveManager]]
7. [[Diplomacy]]
8. [[Regiment]]

이 순서가 좋은 이유는 현재 프로젝트의 실행 흐름이 `GlobalVariables → GameManager → Nation/Province/EconomicEngine` 순서로 이어지기 때문이다.

## 현재 리스크 메모

- `GlobalVariables.LoadData()` 재호출 시 전역 Dictionary 초기화가 부족할 수 있다.
- 일부 문서와 코드 주석이 인코딩 깨짐 상태다.
- `UNIT_TYPE`과 `UNIT_TYPES`처럼 중복 필드가 있다.
- 저장/불러오기 범위가 현재 게임 상태 전체를 덮지 못한다.
- `GovernmentBudget` 정책 기준이 UI마다 다를 수 있다.
- 특수 건물 건설 큐가 아직 미완성이다.
- 이름 문자열 기반 참조가 많아 JSON 이름 변경에 취약하다.
