## 문서 목적

이 문서는 2026-08-22 합의한 건설 시스템 개편 방향을 정리한다.

핵심 목표는 국가가 건물을 직접 시공하는 현재 구조를 없애고, 발주자가 만든 하나의 `ConstructionMandate`를 건설회사가 수주하여 완공하는 구조로 교체하는 것이다.

장기적으로 국가와 프로빈스의 민족집단 모두 발주자가 될 수 있어야 한다. 다만 첫 구현에서는 국가 발주만 활성화하며, 민족집단의 자동 투자 판단과 실제 발주는 실행하지 않는다.

## 확정된 역할

### 국가

- 기반시설, 행정 시설, 군사 시설과 산업 건물을 발주할 수 있다.
- 건설 대상과 위치를 결정한다.
- `ConstructionMandate`의 발주자가 된다.
- 건물을 직접 시공하거나 직접 공수를 생산하지 않는다.

### 프로빈스 민족집단

- 장기적으로 자신의 자산과 예상 수익을 바탕으로 산업 건물을 발주한다.
- 국가와 동일하게 `IBuildingInvestor`가 될 수 있다.
- 첫 구현에서는 발주 가능한 자료형과 확장 지점만 유지한다.
- 자동 투자 판단, 후보 건물 선정과 실제 발주는 아직 실행하지 않는다.

### 건설회사

- 발주자가 누구인지와 관계없이 `ConstructionMandate`를 수주한다.
- 회사 레벨에 따라 동시에 담당할 수 있는 공사 수가 제한된다.
- 공사에 필요한 공수를 제공하고 진행도를 갱신한다.
- 고용 시스템 연결 전까지는 임시 고정 공수를 사용한다.
- 향후 고용 노동자, 임금, 자재 구매, 공사 대금과 회사 수익을 계산한다.

## 핵심 데이터 모델

`ConstructionMandate`는 발주부터 완공까지 동일한 객체로 유지되는 공사의 단일 원본이다.

```text
ConstructionMandate
  ├─ 발주자: IBuildingInvestor
  ├─ 대상 프로빈스: Province
  ├─ 건물 종류: BuildingType
  ├─ 담당 건설회사: ConstructionCompanyBuilding
  ├─ 필요 공수
  ├─ 잔여 공수
  └─ 상태: ConstructionMandateStatus
```

초기 상태는 다음과 같이 구분한다.

| 상태 | 의미 |
| --- | --- |
| `Requested` | 발주되었지만 아직 건설회사가 배정되지 않음 |
| `Assigned` | 건설회사가 공사를 수주함 |
| `InProgress` | 건설회사가 공수를 투입하고 있음 |
| `Completed` | 공사가 끝나 건물 레벨에 반영됨 |
| `Cancelled` | 완공 전에 취소됨 |

예산, 계약 금액, 소비한 자재와 지급 상태는 경제 시스템 연결 시 추가한다. 초기 구현에서는 확장 가능한 책임 경계만 마련한다.

## 국가 발주 흐름

```text
플레이어가 건설 버튼 선택
  ↓
국가가 ConstructionMandate 생성
  ↓
건설 가능한 인접 프로빈스의 건설회사 탐색
  ↓
여유 슬롯이 있는 건설회사에 같은 Mandate 객체 배정
  ↓
건설회사가 매주 임시 고정 공수 투입
  ↓
잔여 공수가 0이 되면 대상 건물 레벨 증가
  ↓
Mandate를 Completed로 변경하고 회사 슬롯 해제
```

건설회사 배정에 실패한 발주는 `Requested` 상태로 남긴다. 이후 건설회사의 슬롯이 비면 다시 배정을 시도할 수 있도록 설계한다.

### 초기 건설회사

건설회사가 하나도 없으면 첫 건설회사를 시공할 주체도 없는 순환 문제가 생긴다. 따라서 플레이어 국가 `Nation1`의 수도 `Bebino`에 1레벨 건설회사를 초기 데이터로 배치한다.

데이터 로더는 해당 건물 종류를 일반 `Building`이 아닌 `ConstructionCompanyBuilding`으로 생성해야 한다. 이후 추가 건설회사는 기존 건설회사가 수행하는 일반 Mandate 흐름으로 건설한다.

## 단일 원본 원칙

국가, UI와 건설회사는 모두 같은 `ConstructionMandate` 인스턴스를 참조해야 한다.

현재처럼 국가의 `BuildingReservation`, 건설회사용으로 새로 생성한 `BuildingReservation`, `Nation.buildingsInProgress`가 각각 별도 공사를 표현해서는 안 된다.

```text
기존
  한 번의 발주
    ├─ ConstructionRequest의 BuildingReservation
    ├─ 건설회사에 전달되는 별도 BuildingReservation
    └─ Nation의 Building 대기열

개편
  한 번의 발주
    └─ 하나의 ConstructionMandate
         ├─ 국가가 조회
         ├─ UI가 표시
         └─ 건설회사가 진행
```

## 첫 구현 범위

### 포함

- `ConstructionMandate`와 상태 모델 추가
- 국가가 Mandate를 생성하고 보유하는 발주 API
- 인접 건설회사 탐색과 같은 Mandate 객체 배정
- 건설회사의 슬롯 관리와 주간 공사 진행
- 완공 시 프로빈스 건물 레벨 반영
- UI 건설 버튼과 대기열을 새 Mandate 흐름에 연결
- 건설회사 건물의 전용 인스턴스 생성 경로와 초기 1레벨 건설회사 데이터
- 민족집단을 미래 발주자로 사용할 수 있는 타입 경계 유지

### 제외

- 민족집단의 자동 투자 판단과 실제 발주
- 회사별 입찰, 가격 제안과 플레이어의 회사 선택
- 노동자 채용과 직업별 공수 계산
- 임금과 공사 대금 지급
- 시장을 통한 건설 자재 구매와 실제 소비
- 민간 건물의 수익성 예측
- 진행 중인 Mandate의 저장 및 불러오기

## 임시 공수 처리

고용 시스템이 연결되기 전까지 기존의 고정 주간 공수를 임시 값으로 사용한다. 다만 공수의 주체는 국가가 아니라 건설회사다.

이 임시 처리는 다음 교체 지점을 명확히 가진다.

```text
현재 임시 계산
건설회사 레벨과 고정값 → 주간 공수

향후 계산
건설회사에 고용된 직업별 노동자
  × 연령별 노동 참여율
  × 직업 효율
  × 임금 지급 여부
  → 주간 공수
```

국가는 공수 계산에 관여하지 않는다.

## 기존 구조의 교체 방향

- `BuildingReservation`의 역할은 `ConstructionMandate`로 교체한다.
- `BuildingInProgress`가 별도의 공사 정보를 복제하지 않도록 한다. 필요하면 회사 슬롯이 Mandate를 직접 참조한다.
- `Nation.buildingsInProgress`와 국가의 직접 `ProgressBuild()` 흐름을 제거한다.
- `ConstructionRequest`는 국가의 Mandate 목록 역할로 축소하거나, 별도 의미가 없다면 Mandate 컬렉션으로 교체한다.
- UI는 Province의 미완공 `Building` 객체가 아니라 Mandate의 잔여 공수와 상태를 표시한다.

## 불변 조건

- 한 번의 건설 명령은 정확히 하나의 Mandate를 만든다.
- 하나의 Mandate는 동시에 둘 이상의 건설회사에 배정될 수 없다.
- `Completed` 또는 `Cancelled` 상태의 Mandate에는 공수를 추가할 수 없다.
- 건물 레벨 증가는 Mandate 하나당 정확히 한 번만 발생한다.
- 회사 슬롯은 Mandate가 완료되거나 취소될 때 반드시 해제된다.
- 민족집단의 자동 투자 기능이 비활성화된 동안 민족집단은 Mandate를 자동 생성하지 않는다.

## 이후 확장 순서

1. 건설회사 노동자 고용과 실제 공수 계산
2. 건설 자재의 시장 구매와 소비
3. 국가 예산에서 공사 대금 지급
4. 건설회사 임금 지급과 수익 계산
5. 민족집단의 자산 및 예상 수익 기반 투자 판단
6. 여러 건설회사의 입찰과 수주 경쟁

이 순서에서는 국가 발주 건설이 먼저 고용과 시장에 수요를 만들고, 그 흐름이 안정된 뒤 민간 투자를 활성화한다.

## 완료 기준

- 국가가 건설 버튼을 누르면 Mandate가 하나만 생성된다.
- 해당 Mandate가 여유 슬롯이 있는 건설회사 한 곳에 배정된다.
- 국가의 직접 공수 없이 건설회사 측 공수로만 공사가 진행된다.
- 완공하면 대상 Province의 건물 레벨이 한 번 증가한다.
- 완공한 Mandate와 회사 슬롯이 정상적으로 정리된다.
- 건설회사가 없거나 슬롯이 가득 찬 경우 발주가 사라지지 않고 대기한다.
- 초기 데이터의 건설회사가 일반 `Building`이 아니라 `ConstructionCompanyBuilding`으로 로드된다.
- 민족집단은 발주자 타입으로 사용할 수 있지만 자동 투자는 발생하지 않는다.
