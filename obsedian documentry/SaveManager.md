# 저장과 불러오기

## 게임 흐름

`GameManager.Start()`에서 기본 정의를 로드한 뒤 새 게임 또는 저장 복원으로 분기한다. 새 게임만 `EconomicInitializer.Initialize()`와 초기 고용 배분을 실행한다. 복원에서는 저장된 잔액과 고용 계약을 재구성하므로 초기 자본 지급이나 임금 지급이 중복되지 않는다.

일간 날짜 진행 이후 주간 급여 → 건설 조달·시공 → 생산 → 소비 → GDP·정책·물가 처리를 수행한다. 저장에는 날짜뿐 아니라 주간 카운터, 마지막 급여 처리 주차, 속도와 일시정지 상태도 포함된다.

`daySimulationEvent`는 실제 하루 진행 때만 전투를 처리한다. `dayUIEvent`는 초기 표시와 일시정지 등 UI 갱신용이므로 로드 직후 추가 전투 피해가 발생하지 않는다.

## 형식 1의 저장 범위

- 국가: 영토·수도·색상, 연구·버프, GDP와 4주 기록, 연구 기금, 정책 예산, 물가와 이력.
- 지역: 도로·황폐도·연결 상태, 인접 지역, 종족·문화별 64비트 연령 인구, 생활 수준·배당, 일반·특수 건물.
- 경제: 국가·중립 지역의 계좌와 통화 장부, 통화량·세율·주간 세수·거래 내역, 공급자 계좌별 재고와 가격·수요·공급.
- 고용: 건물과 민족 집단별 고용 계약, 마지막 급여 처리 주차.
- 건설: 위임 목록과 완료·취소 기록, 투자자·소유자·담당 회사·슬롯, 에스크로, 공사비, 자재 요구·취득·소모량, 정확한 decimal 진행량.
- 군사: 연대 ID·위치·상태, 부대 정원·병력, 활성 연대, 전투 참가자와 외교 관계.
- 세션: 유저와 플레이어, 날짜, 주간 카운터, 속도와 일시정지.

상품·건물·연구 등 기본 정의는 Resources의 현재 카탈로그를 참조한다. 진행 중인 건설 계약의 자재·공사비·인시는 저장 당시 값을 유지한다. 카탈로그의 필수 항목이나 시나리오의 국가·지역 구성이 맞지 않으면 복원을 거절한다.

## 파일과 실패 처리

저장 위치는 `Application.persistentDataPath/<이름>.json`이다. 경로 구분자와 유효하지 않은 파일명은 거절한다. 직렬화한 상태가 복원 가능한지 검증한 다음 `.tmp`에 기록하고, 기존 파일을 원자적으로 교체하면서 이전 파일을 `.bak`으로 보관한다.

불러오기는 `GameSaveState.Restore()`에서 별도 객체들을 구성하고 계좌·통화량·고용·군사 참조를 검증한 뒤 `Apply()`로 전역 레지스트리, 게임 매니저, 인접 지역, 건설 추적 및 전투 매니저에 동일한 인스턴스를 연결한다. 검증 실패 시 기존 게임을 변경하지 않는다.

저장 성공 때만 기존 UI 흐름대로 메인 메뉴로 이동한다. 실패하면 오류 메시지를 표시하며 현재 게임을 유지한다. 시작 시 선택한 파일을 읽지 못하면 새 게임으로 조용히 대체하지 않고 메뉴로 돌아간다.

이전 무버전 파일은 날짜·국가 등 일부 값만 갖고 있으며 경제·건설 상태가 누락되어 있으므로 자동 변환하지 않는다. 기존 파일은 삭제하지 않고 호환되지 않는 형식임을 알린다. 새 게임에서 형식 1 저장 파일을 만들어야 한다.

## 회귀 검증

`Assets/Tests/EditMode/SaveRoundTripTests.cs`에서 실제 Resources 데이터로 JSON 왕복, 다음 주 경제 결과, 건설 완료·취소, 전투, 중립 지역, Int32 초과 인구, 파일 덮어쓰기·백업, 잘못된 파일 및 실패 시 상태 보존을 검증한다.
